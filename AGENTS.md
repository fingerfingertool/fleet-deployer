# Development rules

When doing development work in this repo, relevant superpowers skills
MUST be used — this is not optional.

- Before ANY response or action (including clarifying questions, code
  exploration, or checking files), check whether a superpowers skill
  applies. If one applies, invoke it first and follow it exactly.
- New subsystem or architectural change → `brainstorming` first, then
  `writing-plans`, then `subagent-driven-development` (or
  `executing-plans`) to implement.
- Bug, test failure, or unexpected behavior → `systematic-debugging`
  before proposing fixes.
- Feature or bugfix implementation → `test-driven-development`.
- About to claim work complete/fixed/passing → `verification-before-completion`
  (run the checks, confirm output, evidence before assertions).
- If in doubt whether a skill applies, invoke it. "Simple" tasks still
  get a short design plus explicit approval before implementation.
